# راهنمای ارتقا به 10X Super Admin

## پیش‌نیازها
- Node.js سازگار با پروژه (نسخه 22 توصیه می‌شود)
- MySQL سازگار با Prisma
- مقادیر محرمانه در secret manager یا فایل `.env` محلی (هرگز داخل ZIP توزیع نشود)

## نصب و ارتقا
1. از سورس و دیتابیس نسخه فعلی نسخه پشتیبان بگیرید.
2. ZIP را در مسیر انتشار جدید استخراج کنید؛ روی پوشه نسخه زنده overwrite نکنید.
3. فایل `.env.example` را به `.env` محلی تبدیل و `DATABASE_URL`، `ADMIN_SESSION_SECRET` و تنظیمات ربات را در محیط امن مقداردهی کنید.
4. وابستگی‌ها را نصب کنید: `npm ci`.
5. Prisma Client را بسازید: `npm run db:generate`.
6. migrationها را اعمال کنید: `npm run db:migrate`.
7. تست‌ها و Build را اجرا کنید: `npm test && npm run build`.
8. سرویس API و Bot را با روش systemd مستندشده در `docs/` راه‌اندازی/به‌روزرسانی کنید.
9. سلامت `/health`، ورود مدیر و Mini App را روی محیط staging بررسی کنید.

## Migration جدید
`20261030170000_content_versions` جدول `ContentPageVersion` را اضافه می‌کند. این جدول snapshotهای صفحه شامل slug، شماره نسخه، عنوان، بلوک‌ها، وضعیت انتشار و شناسه مدیر ثبت‌کننده را نگه می‌دارد. migration قبل از اجرا روی دیتابیس اصلی باید در staging بررسی شود.

## بازگشت نسخه برنامه
- ترافیک را به نسخه قبلی منتقل کنید یا سرویس‌های نسخه جدید را متوقف کنید.
- نسخه قبلی سورس را از release قبلی بازیابی کنید.
- اگر migration جدید اعمال شده باشد، جدول `ContentPageVersion` را حذف نکنید؛ نسخه قبلی برنامه به جدول جدید وابسته نیست و نگه‌داشتن آن برای حفظ تاریخچه امن‌تر است.
- برای بازگردانی دیتابیس به نقطه قبل از migration، فقط از backup کامل و تأییدشده MySQL استفاده کنید؛ بازگردانی دیتابیس ممکن است تغییرات بعد از backup را از بین ببرد.

## بکاپ
روش پایه در `docs/backup-and-restore.md` آمده است. پیش از migration از `mysqldump --single-transaction` استفاده کنید و بازیابی را ابتدا روی دیتابیس جداگانه تمرین کنید.

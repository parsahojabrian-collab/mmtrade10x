## اصلاح جدید

در apps/api/public/admin.html، منوی موبایل P53 و بازیابی منوی P52 به navigateManagement متصل شدند. فراخوانی مستقیم show('objectStudio') به دلیل نبودن این شناسه در VIEWS و شرط ابتدای show کاری انجام نمی‌داد. مسیر مشترک ابتدا pages و سپس MMTradeObjectStudioOpen را اجرا می‌کند و محدودیت SUPER_ADMIN را حفظ می‌کند.

سه تست رفتاری در tests/admin-navigation.test.mjs اضافه شد: بازکردن Object Studio از منوی موبایل، حفظ مسیر معمول users و بازکردن Object Studio از منوی بازیابی. دو مورد اول مربوط به Object Studio قبل از اصلاح شکست خوردند و بعد از اصلاح پاس شدند.

## شواهد

- npm test: هر ۱۴ فایل تست پاس شد (این عدد شمار فایل‌های تست است، نه مجموع زیرتست‌ها).
- node tests/admin-navigation.test.mjs: هر ۳ زیرتست پاس شد.
- ۵۲ بررسی syntax برای فایل‌های JavaScript، TypeScript و اسکریپت‌های درون admin.html: بدون خطا.
- پوشه packages از کامیت مبنا در GitHub فقط برای تکمیل آزمون محلی خوانده شد؛ در بسته ارسالی نبود. اسکریپت آماده‌سازی آن را از همان کامیت worktree می‌گیرد و نسخه محلی را جایگزین نمی‌کند. tsconfig ارسالی حفظ شد.
- npm run build در محیط بررسی اجرا نشد: وابستگی TypeScript نصب نبود (tsc: not found). صحت build روی سرور هنوز باید اثبات شود.
- اجرای مرورگر، Safari/Windows واقعی، اتصال دیتابیس و API زنده بررسی نشده‌اند.

## اجرا روی سرور

فایل prepare-integration.py را در /root ذخیره و اجرا کنید:

    python3 /root/prepare-integration.py /root/miniapp10x

این ابزار ابتدا هش همه ۲۱۰ فایل ارسالی، کامیت مبنا و وضعیت packages/tsconfig را بررسی می‌کند؛ در صورت تفاوت متوقف می‌شود. سپس یک worktree و برنچ جدا از کامیت مبنا می‌سازد، سورس موجود ارسالی را به آن کپی می‌کند، اصلاح منو، تست و این گزارش را اضافه می‌کند و تست‌ها را اجرا می‌کند. اگر node_modules روی سرور موجود باشد، برای build به صورت موقت به همان وابستگی‌ها پیوند می‌دهد. TypeScript با --noEmit اجرا می‌شود و چیزی در dist نمی‌نویسد.

تنها فایل‌های صریحاً فهرست‌شده stage می‌شوند. .gitignore فعلی هم در worktree حفظ می‌شود. .env، فایل owner، بکاپ‌ها، فایل‌های موقت و نصب‌کننده‌های ریشه stage نمی‌شوند. فایل‌های جدیدی که بعد از ارسال بسته ساخته شده‌اند وارد این ادغام نمی‌شوند.

ابزار commit، push، merge در main، نصب وابستگی، تغییر دیتابیس، restart یا انتشار انجام نمی‌دهد. سورس اصلی در /root/miniapp10x دست‌نخورده می‌ماند. خروجی آخر مسیر worktree، برنچ و نتیجه تست/کامپایل را نشان می‌دهد؛ این خروجی را برای مرحله ثبت تغییرات بفرستید.

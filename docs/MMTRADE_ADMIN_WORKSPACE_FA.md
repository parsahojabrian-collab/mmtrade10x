# پنل مدیریت: اصلاح مستقیم سورس

مبنا: کامیت 12e1a8e789b0286eb1d4d6fd5c89a971e7863d4b مخزن mmtrade10x.

این تحویل شامل فایل‌های کامل ویرایش‌شده در مسیر اصلی پروژه است، نه diff، پچ یا نصب‌کننده. بسته جایگزین کل مخزن نیست: سایر فایل‌ها و دارایی‌های موجود در کامیت مبنا حفظ می‌شوند.

## تغییرات

- پنج گروه ثابت برای ناوبری، بازشدن گروه فعال، عنوان مسیر، فرم ورود قابل ارسال با Enter و پیام‌های وضعیت قابل خواندن برای ابزارهای دسترس‌پذیری.
- مدیریت صفحات با جست‌وجو، فیلتر وضعیت، آمار واقعی پاسخ API، صفحه شروع، وضعیت انتشار و ورودی ویرایشگر مناسب همان صفحه.
- نوار ثابت ذخیره/انتشار، خطاهای پایدار، حالت درحال انجام عملیات، حفظ ویرایش جدید هنگام پاسخ ذخیره و جلوگیری از خروج ناخواسته.
- کنترل مشترک تغییرات ذخیره‌نشده برای مدیریت صفحات، Object Studio، ویرایشگر قدیمی و استودیوی بصری داخل iframe.
- انتشار یکپارچه محتوا و چیدمان در یک تراکنش دیتابیس؛ نقش‌های فاقد SUPER_ADMIN اجازه انتشار چیدمان از مسیر مشترک ندارند.
- توکن نسخه محتوا در API و ارسال آن از ویرایشگرهای به‌روز؛ پاسخ 409 برای ذخیره/انتشار نسخه قدیمی.
- قفل نوشتن هر صفحه در جدول موجود SystemSetting، مشترک بین مسیرهای محتوا و چیدمان. این قفل دیتابیسی است و محدود به یک process نیست.
- شناسه نسخه چیدمان پس از انتشار به کلاینت برمی‌گردد؛ تغییرات محلی جدید در زمان درخواست انتشار حفظ می‌شوند.
- برطرف‌شدن رقابت بارگذاری ماژول مدیریت صفحات؛ آماده‌شدن DOM و اسکریپت‌های deferred پیش از ساخت آن view انتظار کشیده می‌شود.
- حذف سه پوسته ظاهری تکراری و ورودی شناور تشخیصی قدیمی با polling مکرر. استودیوی قدیمی و ورودی صریح آن نگه داشته شده‌اند.

## سازگاری

- تغییر schema، migration، حذف داده و تغییر احراز هویت انجام نشده است.
- expectedRevision در API برای سازگاری با کلاینت‌های قدیمی اختیاری است. کلاینت‌های جدید آن را ارسال می‌کنند؛ کلاینت قدیمی فاقد این فیلد همچنان می‌تواند بدون کنترل نسخه بنویسد.
- تاریخچه‌های محتوا و چیدمان موجود حفظ شده‌اند. ابزار واحد بازگردانی هم‌زمان این دو تاریخچه در این مرحله اضافه نشده است.
- انتشار صفحه کامل از استودیوی بصری یک درخواست است. API مستقل قدیمی انتشار چیدمان برای سازگاری باقی مانده و از همان قفل نوشتن استفاده می‌کند.
- این مرحله پوسته پنل و مدیریت صفحات را یکپارچه می‌کند؛ بازنویسی کامل همه بخش‌های کاربران، گزارش‌ها و تنظیمات نیست.

## اعتبارسنجی

- npm run build: پاس، پس از تولید Prisma Client از schema موجود؛ بدون اتصال یا تغییر دیتابیس.
- npm test: همه ۱۶ فایل تست پاس.
- اجرای تفصیلی Node: ۱۱۴ تست پاس، صفر شکست.
- تست API از Fastify واقعی و handler فعلی سورس استفاده می‌کند. ذخیره‌ساز آزمایشی تراکنش و rollback را شبیه‌سازی می‌کند: تداخل دو ذخیره، انتشار نسخه قدیمی، خطای نسخه چیدمان، خطای دیتابیس بعد از تغییر چیدمان، انتشار موفق مشترک و منع نقش غیرمجاز بررسی شده‌اند.
- مرورگر Chromium محلی در ابعاد ۱۴۴۰×۱۰۰۰ و ۳۹۰×۸۴۴، با پاسخ‌های آزمایشی API: جست‌وجو، ذخیره هم‌زمان با تایپ، لغو خروج، لغو reload در Object Studio، خروج بدون ذخیره، تأخیر بارگذاری ماژول و نبود overflow افقی بررسی شدند.
- تصاویر پیش‌نمایش با داده آزمایشی ساخته شده‌اند و تصویر محیط زنده نیستند.
- تست اتصال واقعی MySQL، Safari/iOS واقعی، نسخه زنده پنل و انتشار روی سرور در این محیط انجام نشده است.

## اعمال سورس و انتشار

بسته ابتدا در یک worktree تازه از کامیت مبنا باز شود. وابستگی جدیدی اضافه نشده؛ می‌توان از node_modules موجود سرور برای تست و build نسخه جدا استفاده کرد. پس از مشاهده خروجی تست و build، تغییرات همان فایل‌های سورس باید commit و با main ادغام شوند.

تغییر source روی GitHub، نسخه فعال API یا فایل‌های سرو‌شده توسط Nginx را به‌تنهایی به‌روز نمی‌کند. در این سرور API از /root/miniapp10x و وب از /srv/tenx-public ارائه می‌شود. انتشار باید هماهنگ باشد: API جدید قبل از فعال‌شدن رابط جدید آماده شود؛ سپس فایل‌های استاتیک جدید و admin.html با نسخه هماهنگ منتشر شوند. تنظیمات محیط، uploadها و داده‌ها حفظ شوند.

قبل از انتشار، بکاپ موجود و آرشیوهای root نگه داشته شوند. گزارش خروجی تست و build روی سرور برای بررسی نهایی ارسال شود؛ بسته هیچ restart یا نصب خودکاری ندارد.

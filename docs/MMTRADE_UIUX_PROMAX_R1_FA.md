# ممیزی و بازطراحی سراسری MMTRADE — UI/UX Pro Max R1

**وضعیت:** Draft / Review-only — بدون ادغام در main، بدون انتشار زنده، بدون دستکاری API، دیتابیس، ربات تلگرام یا فایل‌های تصویر.

**مبنا:** شاخه main در کامیت \`6b5d2af7f5a4a4d249e279be3bf4e82a033440c8\`؛ مرجع طراحی \`nextlevelbuilder/ui-ux-pro-max-skill\` (قواعد Accessibility، Touch، Performance، Layout/RTL، Typography، Navigation و Dark-mode/Glass).

## محدودیت طراحی

- **حفظ کامل هویت:** بک‌گراند سینمایی، کوه و تعداد پله‌های هوم P74، مکعب، لوگوها، تصاویر اختصاصی، برند سبز زمردی/طلایی و نوار پایین Liquid Glass به قوت خود باقی‌اند.
- **بازطراحی یکپارچه:** تثبیت توکن‌های رنگ، حاشیه، سایه، فوکوس، تعامل، خوانایی و فونت در \`public/miniapp/shared/mm-uiux-promax-r1.css\`؛ این لایه بعد از CSSهای قدیمی بارگذاری می‌شود تا جداگانه قابل حذف باشد.
- **فونت:** Peyda با ۱۸ وزن/نسخه استاندارد و FaNum، با قرارداد نصب خصوصی. Doran برای تیترهای نمایشی شاخص حفظ می‌شود؛ نام کاربری و اعداد حساب با تغییر اجباری رقم مواجه نمی‌شوند.
- **RTL و دسترس‌پذیری:** فوکوس قابل‌مشاهده، انتخاب متن خوانا، tap feedback، reduced motion، عدم اختلال در safe area و حذف \`user-scalable=no\` از ورودی اصلی.
- **حفظ منطق:** هیچ تغییری در \`apps/bot/src/index.ts\`، \`apps/api/src/index.ts\`، Prisma، route resolver یا JavaScript تعاملی اجرا نشده است. در UI داخل خود چت تلگرام نمی‌توان فونت سفارشی اعمال کرد.

## پوشش کد

۲۷ ورودی HTML فعال زیر \`public/miniapp\` و \`apps/api/public\` اصلاح شده‌اند، از جمله:
- هوم و سناریوهای پیش‌نمایش P74
- نوار پایین مشترک و مسیر ۵ تب
- آکادمی و مراحل آموزشی، چالش 10X، Copy Trading Academy
- اتصال ePlanet و صفحه مدیریت مراحل آن
- پروفایل P77 و ادیتور، مرکز پشتیبانی P78 و پیش‌نمایش‌های آن
- Visual Studio / Object Studio، Academy Studio و پنل مدیریت مرکزی و Team Admin
- صفحات سفارشی و Command Center

فایل‌های \`academy-content/**/live.html\` و \`source.html\` تاریخچه/اسنپ‌شات هستند و عمداً بازنویسی نشده‌اند.

## ایمنی و بازگشت

لایه UI جدید با حذف یک \`<link>\` با شناسه/نسخه مشخص در هر ورودی و حذف دو بلوک CSS مخصوص admin/team قابل بازگشت است؛ اما پیشنهاد اصلی **بازگرداندن commit** یا revert کامل Pull Request است. هیچ patch روی فایل‌های API و سرور زنده اجرا نشده است.

فایل فونت‌ها تجاری‌اند؛ **فونت باینری را در مخزن عمومی commit نکنید.** ابتدا صحت مجوز self-hosting را بررسی و سپس بسته خصوصی فونت را به مسیر \`public/miniapp/fonts/peyda/\` در staging نصب کنید.

## صحت‌سنجی انجام‌شده

- اتصال لایه بازطراحی در همه ۲۷ ورودی GitHub دوباره خوانده شد و برای هرکدام یک بار تأیید شد.
- فایل‌های HTML همچنان \`dir=rtl\` دارند.
- توازن باز و بسته شدن بلوک‌های CSS مشترک کنترل شد (بررسی ساختاری ابتدایی، نه جایگزین CSS parser یا تست مرورگر).
- شش تست نصب‌کننده مستقلِ بدون فایل فونت (نصب/rollback، بکاپ فایل قبلی، کنترل تغییر سورس، الزام وجود شاخه طراحی، منع live-root و تشخیص آرشیو ناقص) با موفقیت در محیط آزمون اجرا شدند؛ `audit` روی آرشیو اصلی ارسالی نیز PASS شد.
- پنج تست قراردادی Node در \`tests/uiux-promax-r1.test.mjs\` به شاخه اضافه شده‌اند.

## الزامات قبل از ادغام/انتشار

1. در checkout مجزا: \`node --test tests/uiux-promax-r1.test.mjs\`، \`npm test\`، \`npm run build\` و بررسی خطاهای کنسول.
2. تطبیق سرویس زنده با سورس GitHub از طریق دستورالعمل P75 در مستندات پروژه؛ مخزن به‌تنهایی منبع اثبات وضعیت live نیست.
3. بررسی چیدمان با Chromium و Telegram WebView در عرض‌های ۳۲۰، ۳۷۵، ۳۹۰، ۴۳۰ و ۷۶۸ پیکسل؛ به‌خصوص سطرهای طولانی فارسی، کارت‌ها، modal، متن ورودی و safe area.
4. بررسی واقعی بارگذاری font با Network/Computed Styles؛ نبود فونت روی سرور باعث fallback می‌شود.
5. بررسی Contrast حداقل 4.5:1 برای متن معمول، 3:1 برای عناصر غیرمتنی مهم و دکمه‌های تعاملی با لمس مؤثر ۴۴ تا ۴۸ واحد بر حسب پلتفرم.
6. انجام snapshot بصری قبل/بعد از Home، Profile، Support، Academy، ePlanet، Copy Trading و Studio، بررسی چیدمان landscape و reduced-motion.
7. تأیید جداگانه کاربر قبل از merge و قبل از deploy یا restart.

**محدودیت روشن:** بازطراحی کد و پوشش ورودی‌ها انجام شده، ولی تست مرورگر و Telegram WebView روی سایت زنده و تطبیق فنی با سرویس عملیاتی هنوز انجام نشده؛ تا آن زمان وضعیت انتشار، «آماده بازبینی» است نه «آماده تولید».

# گزارش باگ‌یابی استاتیک MMTRADE10X — ۲۳ نوامبر ۲۰۲۶

## دامنه و محدودیت
مبنا: شاخه اصلی GitHub مخزن `parsahojabrian-collab/mmtrade10x`.
بررسی انجام‌شده: ساختار مخزن، سورس اصلی ربات تلگرام (`apps/bot/src`)، کدهای احراز هویت، صف اعلان، مدل‌های Prisma و migrationها، نقاط حساس API و سیستم‌های ناوبری P74. این یک **بازبینی استاتیک و هدفمند** است؛ اجرای واقعی `npm test`، کامپایل کامل TypeScript، تست MySQL/Telegram، مقایسه فایل‌های زنده با Source و اسکن کامل تک‌تک فایل‌های UI در این محیط انجام نشده است.

## خطاهای تأییدشده و اصلاح‌شده در PR این گزارش
1. **ناوبری تکراری (UI، متوسط):** `public/miniapp/index.html` هم `mf-navigation.js` و هم `mm-bottom-nav.js` را بارگذاری می‌کند. `mf-navigation.js` یک `.mf-global-bottom-nav` جدا می‌سازد، اما `mm-bottom-nav.css` تا پیش از اصلاح این کلاس را پنهان نمی‌کرد. اصلاح: مخفی‌کردن legacy nav فقط وقتی `html.mmu-nav-ready` فعال است.
2. **بی‌اثر شدن انقضای initData در پیکربندی نامعتبر (امنیتی، بالا در صورت پیکربندی غلط):** API مقدار `TELEGRAM_INITDATA_MAX_AGE_SECONDS` را با `Number(...)` می‌خواند. اگر حاصل `NaN` باشد، شرط `now-authDate > maxAgeSeconds` همواره false است و توکن امضاشده قدیمی منقضی نمی‌شود. اصلاح: رد مقدارهای غیرمتناهی، صفر یا منفی در `validateTelegramInitData`، همراه با تست.
3. **به‌روزرسانی نیمه‌کاره تنظیمات مدیریت (یکپارچگی داده، متوسط):** `PUT /admin/settings` تغییر تنظیمات را commit می‌کرد و سپس Audit Log را جداگانه ثبت می‌کرد. شکست ثبت Audit Log باعث خطای HTTP همراه با تغییر تنظیمات می‌شد. اصلاح: ثبت هر دو در یک تراکنش Prisma.

## ریسک‌های باز که نباید بدون تست عملیاتی اصلاح شوند
1. **اعلان تکراری (متوسط/بالا):** در `apps/bot/src/index.ts` بعد از `bot.api.sendMessage`، وضعیت دیتابیس جداگانه به `SENT` تغییر می‌کند. اگر ارسال موفق ولی commit نهایی ناموفق باشد، retry یا restart می‌تواند پیام را تکرار کند. سیاست تحویل `at-least-once` باید روشن و idempotency/audit طراحی شود؛ صرفاً جابه‌جایی سطرها تضمین `exactly-once` نمی‌دهد.
2. **رضایت بازاریابی و اتصال حساب (بالا از حیث محرمانگی/رضایت):** `mergeWebRegistration` در `apps/bot/src/account-state.ts` تمام `userConsent`های پیش‌ثبت‌نام وب را به Telegram User منتقل می‌کند، حتی زمانی که رضایت SMS از یک فرم وب بدون احراز مالکیت تلفن ایجاد شده است. نیازمند قاعده روشن تأیید رضایت و تست ادغام داده است.
3. **توکن مدیریتی Legacy (بالا در صورت لو رفتن):** `ADMIN_LEGACY_TOKEN_ENABLED !== 'false'` به‌صورت پیش‌فرض ورود با `ADMIN_API_TOKEN` و نقش `SUPER_ADMIN` را مجاز می‌کند. حذف یا غیرفعال‌سازی نیازمند بررسی کلاینت‌های فعلی و مسیر بازیابی مدیر است.
4. **انحراف Source/Live (نامشخص):** وجود سورس در GitHub اثبات نمی‌کند فایل‌های `/srv/tenx-public/miniapp` و فایل اجرایی سرویس با همان نسخه هستند. باید با hash و تست زنده بررسی شود.
5. **فایل‌های اضافی در مخزن (کم تا متوسط):** حدود ۵۴۶ مسیر از `academy-content/mm10-image-venv/` در درخت Git ردیابی شده‌اند، با وجود اینکه `.gitignore` آن‌ها را مستثنا می‌کند. حذف tracked files از مخزن را باید در PR مستقل و با تأیید پشتیبان‌گیری انجام داد.

## بررسی‌های موفق
- ۲۸ مدل Prisma تعریف شده‌اند و در ۱۰ migration، برای هر ۲۸ مدل دستور CREATE TABLE وجود دارد. این بررسی **معادل اعتبارسنجی اجرای migration روی MySQL واقعی نیست**.
- درخواست‌های مهم Mini App از `validateTelegramInitData` و user-scoped queries استفاده می‌کنند؛ از جمله وضعیت ePlanet و فهرست تیکت‌ها.
- مسیرها و دکمه‌های Copy Trade در PR قبلی به `/eplanet` متصل شده‌اند.
- فایل‌های `.env` واقعی در نمای فعلی Git مشاهده نشدند؛ تنها `.env.example` قابل مشاهده بود. این ادعا شامل تمام تاریخچه Git یا سرور نیست.

## کنترل ارجاعات فایل‌های رابط کاربری
- تمام ۲۵ فایل HTML موجود در `public/miniapp` از نظر `src`/`href` مستقیم با مسیر مطلق `/miniapp/` و پسوندهای رایج HTML/CSS/JS/تصویر/فونت با درخت Git بررسی شدند؛ هیچ ارجاع مستقیمی به فایل غایب از Git در این دامنه مشاهده نشد. لینک‌های تولیدشده در JavaScript، مقادیر runtime، URLهای خارجی و دسترسی واقعی HTTP در این کنترل پوشش داده نمی‌شوند.

## گام لازم روی VPS
1. اجرای `node --experimental-strip-types --test --test-concurrency=2 tests/*.test.mjs` با `node_modules` نصب‌شده.
2. اجرای `./node_modules/.bin/tsc --noEmit -p tsconfig.json` برای بررسی نوع‌ها بدون ایجاد فایل build.
3. اجرای `node --check` روی JavaScriptهای فعال.
4. مقایسه hash سورس و Live، بررسی `journalctl` بدون اشتراک‌گذاری توکن و داده کاربران.
5. انجام آزمون Telegram WebView، نقش‌های مدیریت، انتشار Studio، ePlanet و ثبت‌نام در محیط تست.

هیچ تغییر مستقیمی روی VPS، MySQL، Nginx یا سرویس Telegram Bot از این گفت‌وگو اعمال نشده است.

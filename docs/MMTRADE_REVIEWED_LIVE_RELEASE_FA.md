## نتیجه ادغام

پس‌زمینه‌های چندلایه و اعتبارسنجی آن‌ها، لینک مشاهده/کپی صفحه منتشرشده در استودیو، مسیرهای stage2 و ePlanet و copytrade-academy و صفحه اصلی جدید چالش حفظ شدند. ابزار Home یکپارچهٔ main و قابلیت حالت فقط مینی‌اپ و شش اصلاح قبلی هم حفظ شدند. نسخه تکراری Object Studio در admin.html بازگردانده نشد؛ امکان مشاهده و کپی لینک اکنون از فهرست صفحه‌های استودیوی اصلی در دسترس است.

مسیرهای قدیمی مراحل خانه مطابق نسخه زنده‌اند: مرحله ۱ https://mmtrade10x.ir/mmtrade10x، مرحله ۲ /copytrade-academy و مرحله ۴ /eplanet. این نگاشت فقط روی تنظیمات قدیمی بدون stepLinksVersion اعمال می‌شود؛ تنظیمات جدیدِ ویرایش‌شده از href ذخیره‌شده استفاده می‌کنند. ابزار Home و رندر عمومی همین قواعد را دارند؛ بنابراین پس از ذخیره، لینک‌ها ناخواسته به مسیر قدیمی main برنمی‌گردند. URL فایل‌های JS/CSS تغییرکرده هم نسخه جدید cache دارند.

## آماده‌سازی و انتشار

prepare-reviewed-release.py یک worktree به نام /root/miniapp10x-reviewed-release می‌سازد، سورس‌های کامل ادغام‌شده را اعمال می‌کند و تست/build می‌گیرد. فایل‌های مشخص stage می‌شوند؛ commit و push خودکار انجام نمی‌شود.

بعد از ثبت و ارسال این شاخه به main، deploy-reviewed-release.py بدون آرگومان فقط پیش‌بررسی می‌کند. برای استقرار صریح باید --deploy داده شود. اسکریپت commit انتشار و فایل‌های سورس را با manifest بررسی می‌کند؛ تغییرات محلی بررسی‌شده باید با همان آرشیو یا خروجی نهایی یکسان باشند. فایل‌های دیگر فقط وقتی جایگزین می‌شوند که با یکی از نسخه‌های شناخته‌شده Git یا خروجی نهایی برابر باشند. این کنترل هم پوشه سورس و هم /srv/tenx-public را پوشش می‌دهد. اختلاف ناشناخته موجب توقف و تولید آرشیو بررسی می‌شود؛ هیچ فایلی خودسرانه حذف نمی‌شود.

قبل از تعویض، فایل‌های منبع، static و فایل‌های کامپایل‌شده تغییرکرده پشتیبان دارند. API و رباتِ فعال برای تعویض هماهنگ متوقف و مجدداً راه‌اندازی می‌شوند. در صورت خطا فقط فایل‌هایی که اسکریپت تعویض کرده برگردانده می‌شوند. فایل تغییرکرده توسط عامل بیرونی در rollback بازنویسی نمی‌شود و خطا گزارش می‌شود.

این انتشار هیچ migration، db push، تغییر env یا تغییر تنظیمات Nginx ندارد. داده‌ها و uploads حذف نمی‌شوند. ربات غیرفعال بدون درخواست روشن نمی‌شود. وضعیت HTTP/health دیتابیس و HTML پنل و پردازش ربات بررسی می‌شوند؛ اتصال واقعی به Telegram تنها از روی وجود پردازش اثبات نمی‌شود و تست تعاملی /start پس از استقرار لازم است.

حالت فقط مینی‌اپ همچنان پیش‌فرض خاموش است و بعد از استقرار باید در پنل فعال و ذخیره شود. این کار ثبت‌نام تلفنی را به مینی‌اپ منتقل نمی‌کند.

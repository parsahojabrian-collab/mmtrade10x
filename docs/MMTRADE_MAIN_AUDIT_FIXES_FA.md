# اصلاح شش ایراد main

مبنای تغییر: a1af2b4c53ea37cb4479f284aac417ea88c9b475.

- API قدیمی PUT مستقیم محتوا، پاسخ 409 با راهنمای استفاده از ویرایشگر می‌دهد. ویرایشگر فعلی از /draft و /publish استفاده می‌کند؛ این مسیرهای صفحات داخلی اکنون expectedRevision الزامی دارند.
- بازگردانی تاریخچه قدیمی صفحات داخلی فقط پیش‌نویس محتوا را تغییر می‌دهد، revision را بررسی می‌کند و انتشار/چیدمان را تغییر نمی‌دهد. رابط این تفاوت را توضیح می‌دهد. برای بازگردانی جفت محتوا و چیدمان، تاریخچه استودیو برقرار است. API صفحات سفارشی خارج از این تغییر باقی مانده است.
- فهرست تیکت‌ها آخرین ۲۰ پیام را به ترتیب زمانی نشان می‌دهد؛ دکمه پیام‌های قبلی صفحه‌های قدیمی‌تر را می‌گیرد. cursor محدود به همان تیکت است و ترتیب زمان/id تساوی زمان پیام‌ها را هم پوشش می‌دهد. متن پاسخ هنگام دریافت تاریخچه حفظ می‌شود.
- شمارش سوپرادمین‌ها، تغییر نقش/وضعیت و audit در تراکنش با قفل مشترک و ReadCommitted انجام می‌شود. مسیر مدیران بخش‌ها هم بعد از همین قفل، سوپرادمین نبودن هدف را دوباره بررسی می‌کند.
- مسیر اصلی و aliasهای آکادمی به academy-home.html می‌رسند.
- ذخیره تنظیمات ربات دقیقاً ۹ شناسه یکتا و متن‌های بدون تداخل می‌خواهد؛ متن‌های پیش‌فرض قدیمی و منوهای سفارشی هم بررسی می‌شوند. تنظیمات ناسالم قبلاً ذخیره‌شده خودکار بازنویسی نمی‌شوند؛ در پنل متن‌ها را اصلاح و ذخیره کنید.
- پیش‌ثبت‌نام، شماره canonical را به کلید قفل SHA-256 تبدیل می‌کند و وجود کاربر را داخل تراکنش دوباره بررسی می‌کند؛ درخواست تکراری اطلاعات یا رضایت کاربر موجود را تغییر نمی‌دهد. رکوردهای تکراری قبلی خودکار حذف یا ادغام نمی‌شوند.

## اعتبارسنجی

۱۰ تست جدید در main-audit-fixes.test.mjs: هم‌زمانی تغییر مدیر، rollback خطای audit، پیش‌ثبت‌نام هم‌زمان دو قالب شماره، عدم دستکاری کاربر موجود، دریافت همه پیام‌ها بدون تکرار در زمان برابر، cursor نامعتبر و مجوز پشتیبانی، مسدودکردن انتشار قدیمی، الزام revision، بازیابی draft-only و تعارض نسخه، تنظیمات دکمه‌ها و مسیریابی زودهنگام آکادمی.

این تست‌ها با Fastify.inject و callbackهای واقعی استخراج‌شده از API، روی دیتابیس تراکنشی حافظه‌ای اجرا شدند. ۹ تست از ۱۰ تست جدید روی سورس پایه شکست خوردند و هر ۱۰ مورد روی نسخه اصلاح‌شده پاس شدند. npm test و npm run build هم پاس شدند. تست قدیمی نام عملیات audit را با رفتار جدید بازگردانی به پیش‌نویس هماهنگ می‌کند.

دیتابیس پروژه MySQL است. تست روی MySQL واقعی، Telegram واقعی و مرورگر زنده در این محیط انجام نشد؛ قفل‌ها از upsert ردیف مشترک SystemSetting داخل تراکنش استفاده می‌کنند و به تغییر schema نیاز ندارند.

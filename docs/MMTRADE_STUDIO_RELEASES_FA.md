# استودیو و بازیابی نسخه‌ها — سورس اصلی

مبنای این تغییر: 288de1377616ff6e1f4165d3751860a2b1bbab09.

- هر انتشار محتوای صفحه، یک snapshot مشترک از محتوای منتشرشده و چیدمان منتشرشده را در همان تراکنش ذخیره می‌کند.
- «ثبت نقطه بازگشت از نسخه عمومی» وضعیت عمومی فعلی را با چیدمان واقعی همان لحظه ثبت می‌کند؛ پیش‌نویس و انتشار را تغییر نمی‌دهد.
- تاریخچه حداکثر ۵۰ نسخه اخیر منتشرشده/نقطه بازگشت را نمایش می‌دهد. نسخه‌های قدیمی فاقد snapshot مشترک مشخص‌اند و بازیابی هماهنگ برایشان فعال نیست؛ اطلاعات تاریخی حدس زده نمی‌شوند.
- پیش‌نمایش نسخه فقط خواندنی است و هیچ درخواستی برای ذخیره یا انتشار ندارد. خروج از آن به بافر پیش‌نویس محلی برمی‌گردد. iframe در ورود/خروج دوباره بارگذاری می‌شود تا اثر استایل‌های نسخه قبلی باقی نماند.
- تنظیمات اختصاصی Home و Profile نیز از markerهای نسخه به پیش‌نمایش منتقل می‌شوند. پروفایل از مسیر preview مخصوص استفاده می‌کند.
- بازیابی نسخه، محتوا و چیدمان را در یک تراکنش به پیش‌نویس می‌برد؛ نسخه عمومی تا تأیید انتشار تغییر نمی‌کند. هر دو توکن نسخه فعلی برای جلوگیری از بازنویسی هم‌زمان لازم‌اند.
- نوار وضعیت، تغییرات محتوا و چیدمان، پیش‌نویس آماده انتشار و حالت مرور تاریخی را با هم نشان می‌دهد. ابزارهای پیشرفته لایه روی موبایل جمع می‌شوند.

## دامنه و محدودیت

schema یا migration جدید لازم نیست. snapshotها به‌صورت رکوردهای مستقل و غیرقابل بازنویسی در SystemSetting با پیشوند MMVS_RELEASE_V1 ذخیره می‌شوند. برای خواندن/ثبت/بازیابی آن‌ها نقش SUPER_ADMIN لازم است. مسیرهای قدیمی تاریخچه حذف نشده‌اند و بخش قدیمی فقط چیدمان با هشدار مشخص حفظ شده است.

snapshot شامل داده محتوا و layout و آدرس رسانه‌هاست؛ فایل‌های تصاویر، نسخه تاریخی HTML/CSS/JavaScript پایه و داده کاربران را ذخیره نمی‌کند. دارایی‌های رسانه‌ای مورد استفاده نسخه‌ها نباید بدون بررسی حذف شوند. snapshotها حذف خودکار ندارند؛ سیاست نگهداری بعدی باید با نیاز بازیابی تعیین شود.

## بررسی

۱۳۰ تست شامل کنترل تداخل نسخه‌ها، rollback خطای میانه بازیابی، عدم تغییر نسخه عمومی، تشخیص تاریخچه قدیمی و خواندنی‌بودن preview پاس شدند. کامپایل TypeScript نیز پاس شد.

تست API با Fastify واقعی و ذخیره‌ساز تراکنشی آزمایشی انجام شده است؛ آزمون واقعی تراکنش روی MySQL سرور هنوز باید پس از انتشار کنترل شود. تست Chromium با پاسخ‌های آزمایشی API، تاریخچه، پیش‌نمایش، حفظ پیش‌نویس، بازیابی و کنترل موبایل را بررسی می‌کند؛ تصاویر پیش‌نمایش داده آزمایشی دارند.

## استفاده پس از انتشار

۱. استودیو را باز کنید و به تاریخچه نسخه‌ها بروید.
۲. از نسخه عمومی فعلی یک نقطه بازگشت ثبت کنید.
۳. پیش‌نمایش آن را باز کنید و بدون ذخیره به پیش‌نویس خود برگردید.
۴. در یک صفحه آزمایشی بازیابی به پیش‌نویس را امتحان کنید؛ نسخه عمومی باید ثابت بماند.
۵. پس از بررسی پیش‌نمایش، انتشار را تأیید کنید.

این بسته فایل‌های کامل سورس است، نه diff یا patch. ابتدا در worktree جدا روی کامیت مبنا باز شود و npm test و npm run build روی سرور اجرا شوند. انتشار API و فایل‌های static باید هماهنگ باشد. خروجی کامپایل جدید apps/api/src/studio-releases.ts نیز هنگام انتشار ضروری است. فایل‌های .env، uploadها، تنظیمات Nginx و داده کاربران در بسته نیستند.

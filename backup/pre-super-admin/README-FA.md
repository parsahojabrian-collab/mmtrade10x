# پلتفرم 10X — بسته یکپارچه آماده نصب

این بسته از دو آرشیو دریافتی ساخته شده است: صفحات HTML چندصفحه‌ای و بسته به‌روزرسانی API/Bot/Prisma. فایل‌های مفقود لازم برای ساختار اجرا، تنظیمات، اعتبارسنجی Telegram Mini App، migration اولیه، تست و مستندات تکمیل شده‌اند.

> **وضعیت واقعی:** این یک سورس یکپارچه و آماده نصب/پیکربندی است؛ روی سرور شما مستقر نشده و با توکن واقعی تلگرام یا دیتابیس شما آزمایش انتها‌به‌انتها نشده است. به دلیل در دسترس نبودن دانلود وابستگی‌ها در محیط ساخت، نصب npm و build کامل قابل اجرا نبود. تست‌های مستقل و بررسی نحوی فایل‌های TypeScript با Node اجرا شده‌اند.

## اجزای پروژه

- `public/`: ۹ صفحه وب اصلی و صفحات مستقل Telegram Mini App
- `apps/bot/`: ربات grammY با `/start`، بررسی عضویت کانال، رضایت پردازش، دریافت Contact رسمی تلگرام، منو، پشتیبانی و صف اعلان/پیگیری
- `apps/api/`: Fastify API، ثبت‌نام وب، اعتبارسنجی Telegram initData، پنل عملیاتی و API مدیریت
- `packages/db/prisma/`: مدل‌های دیتابیس و migration اولیه MySQL
- `packages/shared/`: اعتبارسنجی رمزنگاری‌شده Telegram Web App initData
- `tests/`: تست‌های مستقل قرارداد API و اعتبارسنجی امضای تلگرام
- `.env.example`: نمونه متغیرهای محیطی بدون هیچ secret واقعی

## نیازمندی‌ها

- Node.js نسخه 22 یا جدیدتر
- npm نسخه 10 یا جدیدتر
- MySQL 8.0+ یا MariaDB سازگار با Prisma MySQL
- دامنه و HTTPS برای Mini App و webhookهای آینده
- توکن ربات از BotFather

## راه‌اندازی محلی / سرور

```bash
# در پوشه ریشه پروژه
cp .env.example .env
# فایل .env را با مقادیر واقعی و محرمانه تکمیل کن
npm install
npm run db:generate
npm run db:migrate
npm run build
```

برای نصب تازه، migration اولیه در `packages/db/prisma/migrations/20261030000000_initial` وجود دارد. پیش از اجرای migration روی دیتابیس موجود، حتماً backup بگیر و وضعیت schema را بررسی کن.

اجرای API و Bot در دو ترمینال/سرویس جداگانه:

```bash
npm run start:api
npm run start:bot
```

در محیط توسعه:

```bash
npm run dev:api
npm run dev:bot
```

سلامت API:

```bash
curl -i http://127.0.0.1:3000/health
```

Mini App: `https://YOUR_DOMAIN/miniapp`
پنل عملیاتی: `https://YOUR_DOMAIN/admin/control`

## تنظیم BotFather و کانال‌ها

1. با BotFather ربات بساز و مقدار `TELEGRAM_BOT_TOKEN` را فقط در `.env` قرار بده.
2. ربات را به کانال‌های اجباری اضافه کن و دسترسی لازم برای مشاهده عضویت اعضا (`getChatMember`) بده؛ برای کانال خصوصی، ربات باید عضو/ادمین کانال باشد.
3. `REQUIRED_CHANNELS` را با شناسه کانال‌ها و جداکننده کاما وارد کن؛ نمونه: `@channel_one,-1001234567890`.
4. `REQUIRED_CHANNEL_LINKS` را با لینک‌های متناظر و جداکننده `;` وارد کن.
5. `ALLOW_NO_REQUIRED_CHANNELS=false` را در حالت عملیاتی نگه دار تا نبود تنظیم کانال باعث عبور ناخواسته نشود.
6. `MINI_APP_URL=https://YOUR_DOMAIN/miniapp` را تنظیم کن.
7. در BotFather دامنه Mini App را تنظیم و دامنه HTTPS را ثبت کن.

Bot به‌صورت پیش‌فرض از **long polling رسمی تلگرام** استفاده می‌کند؛ نیازی به webhook برای شروع فاز اول نیست. در این نسخه حالت webhook پیاده‌سازی نشده است.

## تنظیم پنل مدیریت

یک secret تصادفی حداقل ۳۲ کاراکتری بساز:

```bash
openssl rand -hex 32
```

خروجی را در `ADMIN_API_TOKEN` قرار بده. پنل `/admin/control` و APIهای مدیریتی با هدر `Authorization: Bearer ...` محافظت می‌شوند. توکن فقط در حافظه همان صفحه پنل نگهداری می‌شود.

**محدودیت امنیتی فعلی:** احراز هویت چندمدیره، رمز عبور مدیران و RBAC عملیاتی هنوز پیاده‌سازی نشده است؛ مدل‌های AdminUser و AdminRole در schema هستند اما مسیر ورود و مجوزدهی مبتنی بر نقش به آن‌ها متصل نیست. تا تکمیل این بخش، دسترسی پنل را فقط به مدیر اصلی بده و روی پنل rate limit و محدودیت IP در reverse proxy اعمال کن.

## مسیر ثبت‌نام فاز اول

### ربات تلگرام

`/start` در گفتگوی خصوصی ربات → بررسی عضویت واقعی کانال‌ها با Bot API → رضایت پردازش اطلاعات → دریافت شماره با دکمه رسمی Share Contact → ذخیره کاربر/رضایت/مرحله در دیتابیس → نمایش منو و لینک Mini App.

شماره‌ای که با Contact تلگرام ارسال می‌شود باید متعلق به همان حساب باشد (`contact.user_id === from.id`). شماره تایپ‌شده پذیرفته نمی‌شود. اگر شماره قبلاً از پیش‌ثبت‌نام وب دریافت شده باشد، پس از بررسی عضویت به وضعیت ثبت‌نام اولیه منتقل می‌شود.

### وب‌سایت

فرم پیش‌ثبت‌نام به `POST /public/pre-register` متصل است. رضایت پردازش اجباری و رضایت پیامک اختیاری و مستقل ذخیره می‌شود. ارسال پیامک واقعی در این نسخه فعال نیست.

### پیگیری پنج‌ساعته

Worker ربات، کاربران تلگرامی ناقص را پس از پنج ساعت بی‌فعالیتی وارد صف می‌کند و پیام یادآوری تلگرام می‌فرستد. جلوگیری از تکرار در بازه ۲۴ ساعت اعمال شده است. کاربرانی که فقط فرم وب را ثبت کرده و هرگز ربات را شروع نکرده‌اند، امکان پیام تلگرام ندارند.

## APIهای اصلی

| مسیر | کاربرد |
|---|---|
| `GET /health` | سلامت API و اتصال دیتابیس |
| `POST /public/pre-register` | پیش‌ثبت‌نام وب با رضایت |
| `POST /auth/telegram` | اعتبارسنجی initData سمت سرور |
| `POST /public/tickets` | ثبت تیکت با initData معتبر تلگرام |
| `GET /admin/summary` | خلاصه کاربران |
| `GET /admin/users` | فهرست/جست‌وجوی کاربران |
| `GET, PUT /admin/settings` | تنظیم کانال‌ها و Mini App |
| `PATCH /admin/users/:id` | ویرایش وضعیت کاربر |
| `GET /admin/registrations/incomplete.csv` | خروجی ثبت‌نام ناقص |
| `GET, POST /admin/followups` | مدیریت یادآورها |
| `GET, POST /admin/notifications` | مدیریت صف اعلان |
| `GET /admin/tickets` | فهرست تیکت‌ها |
| `POST /admin/tickets/:id/reply` | پاسخ مدیر به تیکت |
| `GET /admin/audit-logs` | رویدادهای مدیریتی |

تمام مسیرهای `/admin/*` به `ADMIN_API_TOKEN` نیاز دارند.

## استقرار پیشنهادی

- API و Bot را به‌صورت دو سرویس systemd جدا اجرا کن.
- Nginx را به‌عنوان reverse proxy روی پورت 3000 قرار بده.
- TLS را با گواهی معتبر فعال کن.
- فایل `.env` را با مجوز `600` و مالک سرویس نگه دار.
- دسترسی دیتابیس را به دیتابیس همین پروژه محدود کن.
- از دیتابیس روزانه backup بگیر و بازیابی backup را به‌صورت دوره‌ای تست کن.
- جزئیات نمونه systemd و Nginx در `docs/` آمده است.
